> **▶ Try it live:** <https://mahmood726-cyber.github.io/rapidmeta-kit/> — a
> illustrative RapidMeta dashboard for finerenone in CKD, generated by this kit
> and served straight from `docs/`. Click through the Screening, Extraction,
> and Analysis Suite tabs.

Spin up the **full interactive RapidMeta dashboard** for any topic by editing
a small JSON file and running one command. You get the complete workbench —
protocol, search, screening, risk-of-bias, editable extraction, live
  re-pooling, a 28-panel statistics tab, GRADE Summary of Findings, optional WebR
  R-validation, PRISMA flow. The local workbench runs in the browser; the
  WebR validator and source searches require network access.

The heavy engine (~1 MB) and its stat-panel scripts are **pre-built and
bundled**. The only thing that changes per review is a ~20-line config, so an
AI CLI (Gemini, Claude, etc.) on a free / rate-limited key can produce many
dashboards without burning quota.

> Want a *lightweight* static one-page meta-analysis instead (tiny output, no
> interactive engine)? See the sister project
> **[meta-starter-kit](https://github.com/mahmood726-cyber/meta-starter-kit)**.
> This repo is the *full* interactive version.

## ▶️ Use it in 3 steps

1. **Install Python** (once): <https://www.python.org/downloads/> — on
   Windows tick **"Add Python to PATH"** during install.
2. **Run the example.**
   - **Windows:** double-click **`RUN_EXAMPLE.bat`**.
   - **Mac/Linux:** `bash run_example.sh`.
   - **Any terminal:** `python clone.py configs/example_finerenone_ckd.json`
3. **Open** `output/finerenone_ckd.html` in a browser. That is a complete,
    interactive illustrative RapidMeta dashboard for finerenone — click through Screening,
   Extraction, and the Analysis Suite tabs.

## Make your own

1. Copy an example config:
   ```
   copy configs\example_finerenone_ckd.json configs\my_review.json   (Windows)
   cp   configs/example_finerenone_ckd.json configs/my_review.json   (Mac/Linux)
   ```
2. Edit `configs/my_review.json` — set the drug, condition, and trials
   (see [Config](#config)).
3. Build:
   ```
   python clone.py configs/my_review.json
   ```
4. Open `output/<your_slug>.html`.

## Config

Minimum:
```json
{
  "drug": "Finerenone",
  "slug": "finerenone_ckd",
  "condition": "CKD in type 2 diabetes",
  "title": "Finerenone for CKD — illustrative review dashboard",
  "hero_h2": "Finerenone in type 2 diabetes with CKD",
  "nyt_headline": "Two randomized trials of finerenone in diabetic kidney disease",
  "trials": [
    { "nct": "NCT02540993", "name": "FIDELIO-DKD", "year": 2020,
      "tE": 367, "tN": 2833, "cE": 420, "cN": 2841 },
    { "nct": "NCT02545049", "name": "FIGARO-DKD", "year": 2021,
      "tE": 458, "tN": 3686, "cE": 519, "cN": 3666 }
  ]
}
```
- `tE`/`tN` = events/total in the intervention arm; `cE`/`cN` = comparator arm.
- A verified **hazard ratio**, if available, must include its declared type:
  `"publishedHR": 0.86, "hrLCI": 0.75, "hrUCI": 0.99, "reportedEffectType": "HR"`.
  This field **does not support odds ratios, risk ratios, or recurrent-event rate ratios**.
- `tE`/`tN` and `cE`/`cN` must be whole-number patient counts. A source result
  containing *total events* (including repeated events in one person) must not
  be entered as a binomial event count.
- Include `hero_h2` and `nyt_headline` to avoid carrying the source template's
  topic-specific prose into a new dashboard.
- For byte-for-byte repeatability, set an ISO `date` in your config. If omitted,
  the generated publication metadata uses the current build date.
- Optional extras: `comparator`, `hero_h2`, `nyt_headline`, `pico`,
  `acronyms`, per-trial `pmid` / `phase` / `group` / `allOutcomes`, and source URLs.
- See `configs/example_finerenone_ckd.json` for a fully-populated example.

The build prints a `[CONFIG ERROR]` naming exactly what to fix if a field is
missing or malformed.

## How it works

`clone.py` stamps your config onto `template/base_dupilumab_copd.html` (the
validated RapidMeta base, unminified) — it swaps the drug/condition tokens
and replaces the trial dataset — then copies the shared `assets/` folder
(stylesheet, plotly, and the 28 stat-panel scripts) next to your output so it
runs offline. No statistics are recomputed by an LLM; the dashboard does all
analysis in the browser.

## Offline notes

- Everything runs client-side and works offline **once downloaded**, except:
  - **Icons** use a Font Awesome CDN (cosmetic; the page is fully usable
    without them).
  - The live **CT.gov / PubMed lookups** inside the Search tab need internet
    (optional — you can paste/extract data manually).
  - **WebR independent R validation** is optional and initially downloads R and
    packages from external services; it will not run offline on a clean machine.
- Network-meta-analysis plots use the bundled Plotly (`assets/plotly.min.js`)
  — no internet needed.

## What NOT to edit

For normal review creation, only edit `configs/`. Changes to the shared engine,
generator, or validation logic are maintenance tasks requiring tests and review.
`output/` is regenerable.

## Development

The kit is pure-Python stdlib at runtime — `clone.py` has **zero** dependencies
and makes no network calls. Tests and JSON-schema validation are dev-only:

```
pip install -e ".[dev]"   # pytest + jsonschema
python -m pytest          # unit + end-to-end build tests
```

The suite covers the JS-literal rendering (including apostrophe escaping, which
would otherwise break a dashboard), config validation and exit codes, and a
full subprocess build of both bundled example configs. CI runs it on Python
3.9 / 3.11 / 3.13 and smoke-builds the example dashboard
(`.github/workflows/ci.yml`).

The live demo under `docs/` must be regenerated whenever the example config
changes. The CI test suite checks that the emitted demo matches the config:

```
python clone.py configs/example_finerenone_ckd.json --out docs/index.html
```

## Honesty

Each dashboard is an **auto-generated draft**. The kit wires your trial data
into a working analysis app; it cannot judge whether the trials are
clinically combinable or whether the extracted numbers are correct. Verify
inputs against source publications before using or citing any result.

### Why FINEARTS-HF is not included in the finerenone CKD example

The sample intentionally covers **FIDELIO-DKD and FIGARO-DKD only**. Both
enrolled people with type 2 diabetes and chronic kidney disease, and both
reported the four-component cardiovascular composite (CV death, nonfatal MI,
nonfatal stroke, or heart-failure hospitalisation) as a time-to-first-event HR.
Their event counts and reported HRs are not interchangeable statistics.

FINEARTS-HF enrolled people with HFmrEF/HFpEF (not the same CKD/T2D eligibility
population) and its primary result was a **rate ratio for recurrent worsening-HF
events plus CV death**, not a hazard ratio. Labelling it `publishedHR` and
pooling it with the DKD trials was incorrect; it has been removed.

- [FIDELIO-DKD primary publication](https://doi.org/10.1056/NEJMoa2025845)
- [FIGARO-DKD primary publication](https://doi.org/10.1056/NEJMoa2110956)
- [FINEARTS-HF primary publication](https://doi.org/10.1056/NEJMoa2407107)

Other bundled topic configs are illustrative datasets, **not clinically
validated pooled reviews**. In particular, the oxygen and renal-replacement
therapy examples combine mortality outcomes assessed at different timepoints;
those studies need harmonised endpoint/timepoint decisions before inferential
pooling. The conservative-oxygen demo omits ICU-ROX from its statistical inputs
until its published odds ratio can be represented without being mislabelled an HR.
In the sugammadex demo, Togioka's published OR was removed from the HR field;
its separately reported event counts remain.

The scaffold does not independently conduct a systematic search, validate trial
eligibility, adjudicate RoB 2 domains, or provide a verified GRADE certainty
judgement. **An automatically displayed RoB/GRADE value is not a substitute for
an assessor's documented decision**. These tasks require separate human review
and evidence records before publication or regulatory use.
