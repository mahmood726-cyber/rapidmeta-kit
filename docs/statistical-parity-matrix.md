## 28 October 2026 — near-null fixed-time HR-to-NNT arithmetic (draft #66)

**Source-backed bounded defect:** Altman and Andersen (BMJ 1999, doi:[10.1136/bmj.319.7223.1492](https://doi.org/10.1136/bmj.319.7223.1492)) define time-specific NNT from the specified control survival probability S_c(t) and an HR under a proportional-hazards interpretation. The original shipped `nntForHR` computed `Rc - [1-(1-Rc)^HR]` by subtraction and declared any `|ARR| < 1e-9` undefined, even when the NNT was mathematically finite. Actual unmodified JS blob **`929a1f2d37b3b90a12c10e6b0204a912212792d0`** returned **null NNT** for synthetic fixed-time control risk **0.25** at HR **0.9999999999** and **1.0000000001**, despite nonzero ARR approximately ±2.16e-11. This is a numerical-representation defect, *not* a clinical treatment-effect correction.

The amended three distributed `rapidmeta-survival.js` copies use `log1p`/`expm1` to evaluate `ARR=S_c(t)*expm1((HR-1)*log(S_c(t)))` and the treatment event risk without cancellation. They retain null NNT for exact HR=1 and for unrepresentable reciprocals. Positive and negative source-executed Node/pytest tests now cover near-null benefit/harm, tiny baseline risks, exact null, and ordinary values. Added an independently executed **R 4.4.3 base-R** numerical oracle (no metafor needed for this closed-form transform), with a forged-output negative and invalid source refusal. Neither the source data, effect type nor NNT estimand was changed.

## Independent critical methods feedback and named HKSJ variant — 28 October 2026

An **attributable external critical methods assessment** was received from **Dr Yousef Moradi** on 28 October 2026. He independently examined PR #62's description, this parity register and the stated R 4.4.3 / metafor 4.8-0 comparisons. With his explicit permission, the observations are summarised in the [PR discussion](https://github.com/mahmood726-cyber/rapidmeta-kit/pull/62#issuecomment-6478506100). He found the method choices, version pinning, lexical refusals and duplicate-study guards constructive but requested precise method naming and stronger edge-case assessment. **This is an independent, critical *methodology note*, not an independent executed R comparison, line-by-line code audit, GitHub approval, endorsement or clinical-source validation.** There are no formal GitHub review submissions at this checkpoint.

**Definition of the implemented method, k >= 2.** The current `assets/vendor/rapidmeta-survival.js::poolLogRE` uses inverse-variance random-effects weights `w_i = 1 / (v_i + tau2_REML)` and pooled log effect `mu = sum(w_i*y_i)/sum(w_i)`. The residual adjustment is `q* = sum(w_i*(y_i-mu)^2)/(k-1)`; the reported coefficient SE is `sqrt(1/sum(w_i))*sqrt(max(1,q*))`, with confidence limits `mu +/- t_(k-1,0.975)*SE`. Therefore the existing shorthand **“floored HKSJ” explicitly means *modified/ad-hoc Knapp–Hartung* (mKH), flooring the estimated variance adjustment at 1**, rather than standard unmodified HKSJ (`q*` unrestricted) or an arbitrary machine-epsilon floor. The intentionally method-matched comparator is `metafor::rma.uni(...,method="REML",test="adhoc")`; official [metafor documentation](https://rdrr.io/cran/metafor/man/rma.uni.html) confirms that `adhoc` disallows adjustment to an SE smaller than its ordinary unadjusted counterpart. For `k=1`, JS uses its separately documented normal approximation `1.96`, whereas the R comparator uses `qnorm(0.975)`; it is not an mKH fit or bitwise equality. This naming is a description of already committed code, **not** a new claim of method-wide numerical parity.

**Reviewer-requested boundaries:** The existing synthetic R suite includes small-`k` (1/2) positive controls and malformed HR/CI/duplicate evidence refusal; it is not a complete extreme-precision-imbalance sensitivity study. An executable, method-matched R/metafor stress test for strongly unequal study SEs remains **NOT_RUN**; numerical precision near a zero tau² root is also separately tracked in [PR #13](https://github.com/mahmood726-cyber/rapidmeta-kit/pull/13). Source-verified clinical effects, rare-event GLMM and fitted multi-arm NMA/SUCRA remain **BLOCKED/NOT_RUN** as specified below. ## Interpretation and provenance

- **Status** describes the stated *method-specific native-R comparison*, not general engine correctness. `PASS` only where GitHub CI actually executed the pinned R comparator on the stated commit. `NOT_RUN` is not tested; `BLOCKED` has no matched oracle or lacks independently established input/estimand. No `FAIL` is inferred without a failing, matching comparison. Structural JavaScript/pytest passes are **never** a substitute for an R `PASS`.
- **Input SHA** is the full Git **blob SHA-1 of the fixture-containing source file**, not a hash of a separately exported clinical dataset.
