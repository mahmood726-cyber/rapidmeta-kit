## Interpretation and provenance

- **Status** describes the stated *method-specific native-R comparison*, not general engine correctness. `PASS` only where GitHub CI actually executed the pinned R comparator on the stated commit. `NOT_RUN` is not tested; `BLOCKED` has no matched oracle or lacks independently established input/estimand. No `FAIL` is inferred without a failing, matching comparison. Structural JavaScript/pytest passes are **never** a substitute for an R `PASS`.
- **Input SHA** is the full Git **blob SHA-1 of the fixture-containing source file**, not a hash of a separately exported clinical dataset. The linked source file plus the stated commit determines the exact synthetic fixture definition. Input files embed executable code; no original clinical records are represented. Before externally sourced cases are eligible for `PASS`, create a canonical raw-input SHA-256 manifest with study IDs, extraction provenance, outcome/time point, estimator and eligibility decisions.
- **JS version** is the full Git **blob SHA-1 of the actual shipped `assets/vendor` engine** at that row's commit, not a semver release. Reference programs, run URLs and declared tolerances must travel with the result; compare exact Git revisions, not just test names.
- `metafor 4.8-0` rows require **R 4.4.3**, a SHA-256-checked `metafor_4.8-0.tar.gz` (archive hash `59003bece34b2ed39f29dce61ca5a68287be07ec683f2f6c51f17bb50ca87801`), and exact test/method settings. Main's R 4.4.3 job uses **independently written base R, not metafor**. R tests and workflow actions fail rather than silently skip if the required runtime is absent.
- Tolerances below are comparison criteria chosen by existing tests; they are **not clinical acceptance margins**. A local V8 check or copied numerical anchor alone has status `NOT_RUN` for native R parity. "Accepted mismatches" means an explicitly scoped numerical approximation or convention *not treated as equivalent*, never an unexplained discrepancy.
